## How to work here (learned this session — saves real time)
- **Bun:** `export PATH="$HOME/.bun/bin:$PATH"`. Gate before commit: `bun test`, `bunx tsc --noEmit`,
  `bunx biome check ./src ./tests` (Biome uses TABS; `--write` auto-fixes).
- **Delegate big builds to Codex** to conserve orchestrator tokens, then review:
  `setsid nohup ~/.local/bin/codex exec -C <worktree> --sandbox danger-full-access -c
  model_reasoning_effort=high "$(cat brief.md)" > log 2>&1 &` — in a `git worktree` off `main`. Codex
  writes a `*_NOTES.md` when done; verify the gate YOURSELF, review the diff, then pair-review.
- **Pair review every non-trivial change** (both engines) via `scripts/external_review.sh <codex|grok>
  <workdir> <brief> <report>` with `GROK_BIN=$HOME/.grok/bin/grok`. Each brief must ask for
  `VERDICT: APPROVE`/`BLOCK`. **Launch review tasks ONE AT A TIME** — two concurrent background review
  tasks got killed by the harness; a single tracked task survives. Codex sometimes HANGS (stale log
  mtime while the proc is alive) — detect, kill, re-run or adjudicate on the other engine + your own
  verification. Engine quota (harness exit 42) → fall back, note it, retry later.
- **The reviews earn their keep.** They caught real reconciliation bugs (self-ref starvation, subset
  thrash, cross-file cycle gap, hash-scope) and an atlas-refactor regression. Don't skip them for
  correctness-sensitive code; keep trivial changes light.
- **Empirically verify Plane behavior** with throwaway items on the live DATA board (creds in the
  gitignored `.env`; run from inside the repo so `.env` auto-loads) — clean up after. That's how we got
  the point-integer, auto-mirror, and silent-cycle-drop facts.
- **Track this work as markdown handoffs** (brief → report), NOT Plane tickets — planestories dev is a
  cross-repo handoff with the data-platform team (their DATA Plane project tracks the *platform*, not
  this tool). Update `docs/DESIGN_DECISIONS_*` + a report file as you ship.
